## R14 / #136

Original head: `45456c4db1f50e9bbc8dc9823e77c5fb20755a9e`.
The reviewed candidate preserves all integrated R09–R12 and repaired R13 code.

Repairs:

- Adapter stdout/stderr are read incrementally into fixed byte caps, rather than
  accumulated by capture_output and truncated afterwards. Overflow stops the
  owned process group immediately and is an explicit error/flag. UTF-8 repair
  cannot expand the retained text beyond the byte cap.
- The timeout covers stdin writes, inherited pipes and a child that closes its
  pipes but keeps running. Cleanup kills the owned session group after every
  outcome, including parent exit, without a global process kill.
- Child limits run after exec in a fresh interpreter, avoiding Python preexec
  deadlocks in a multithreaded host. A separate bounded pipe reports the limits
  actually applied to that invocation; platform probe output is only diagnostic.
- Manifest reads refuse FIFOs/devices and symlinks before reading. Byte, nesting
  and node limits, finite JSON validation and immutable private serialization
  prevent aliased input/public views from changing installed identity.
- Unknown trust values and boolean registry bounds are refused. Registry digest
  binds trust; enabled and installed counts are distinct. Registry dispatch
  requires current enabled state and reviewed-same-user trust. Declared read
  permissions are compatible names only, not granted capability handles.
- All input/output documents have registered Pydantic-generated schemas and
  production-shape validation tests.

Local validation: 46 extension tests pass, including endless output, non-UTF-8
stderr, a descendant holding pipes, FIFO refusal, mutation after parsing, unknown
trust, finite deadlines, per-invocation limits and disabled dispatch. Final-head
full coverage, Python/macOS, browser and designated actual execution CI remain
required before integration.

This remains a partial Python extension boundary. It does not integrate typed
third-party evaluator/provider plugins or the existing BlockRegistry, provide an
extensions CLI, persist the registry, or isolate malicious code. Same-user code
can access same-user files/network; declarations never enforce OS capabilities.
Disable refuses subsequent registry dispatch and does not cancel an already
running invocation. Full R14 and Checkpoint D acceptance remain open.
