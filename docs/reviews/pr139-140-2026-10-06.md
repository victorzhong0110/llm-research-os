## Review findings and repairs

1. A snapshot could be replaced between image verification and restore. Counts
   and ledger comparison did not bind the copied SQLite bytes to the verified
   manifest. Restore now verifies that private copy's digest and size before
   opening it; the ledger comparison reads the private copy as well.
2. Python restore layout overrides could write outside the new workspace, and
   per-PID staging names allowed concurrent operations to erase each other's
   staging. Overrides stay within the new root; staging paths are unique.
3. Backup manifests used a pre-read stat guard and accepted special files.
   Reads are bounded during the read, and non-regular files are refused.
4. Trial aggregation could clear blockers using substrings of a trial ID; an
   empty blocker list and two records (T1 and REMOTE) reported Checkpoint D true.
   Completed T1–T5 is now required for each of two confirmed participants plus
   one completed remote journey. Failed journeys do not satisfy completion;
   duplicate IDs, blank evidence and inconsistent verdicts are refused.
5. Record counters cannot prove independence, authorization, authentic evidence,
   defect resolution or predecessor acceptance. The aggregate reports task
   coverage separately and always leaves Checkpoint D to maintainer review.
   Regular-file trial document reads are bounded. Scaffold retains the requested
   participant and author.
6. SQLite initialization retained a host-path leak after the earlier four path
   rejections were repaired. Its error is now path-free. Demo hints now quote
   each shell argument, preserving spaces and metacharacters literally.
7. Current documentation contained duplicate/stale package states and claimed
   no CI/browser evidence or no remaining code acceptance gaps. Current records
   are reconciled while historical candidate evidence remains attributable.
